Ask a language model what the broadcast address of `10.20.0.0/22` is and you will
usually get the right answer. Usually. Ask it to decode a JWT and it will happily
"read" base64 in its head and invent a claim or two. Ask it for five UUIDs and you
get five strings that *look* random but were produced by a text predictor.

These are exactly the jobs where you want a deterministic tool, not a guess. The
[Model Context Protocol](https://modelcontextprotocol.io) (MCP) is the standard way
to hand those tools to an agent, and every WebTools tool is available through it.
This guide shows how to plug it in and what your agent can do with it.

## What the server exposes

The MCP endpoint lives at `@@API_BASE@@/mcp`. It speaks **Streamable HTTP** in stateless
mode: no session, no login, no API key. Five tools are registered:

| Tool | What it does | REST equivalent |
|------|--------------|-----------------|
| `calculate_cidr` | Network, broadcast, mask, host range and "is it publicly routable?" for an IPv4 CIDR | `GET`<br />`/api/v1/ip` |
| `decode_jwt` | Header, payload and an expiry analysis with human-readable dates. **No signature check.** | `POST`<br />`/api/v1/jwt` |
| `decode_x509` | Subject, issuer, validity, key, extensions (SAN, key usage…) and fingerprints of a PEM/DER certificate | `POST`<br />`/api/v1/x509` |
| `generate_uuid` | 1–10 UUIDs, version 7 (default) or 4 | `GET`<br />`/api/v1/uuid` |
| `generate_nanoid` | 1–10 NanoIDs with a chosen size and alphabet | `GET`<br />`/api/v1/nanoid` |

All three interfaces (the web pages, the REST API and MCP) call the same shared
code, so the agent sees exactly the numbers you see in the browser.

## Try a few prompts

Once connected, you don't need to name the tools. Describe the task and let the
agent pick:

- *"We were given 10.20.0.0/22 for the new office. How many hosts fit, and what's the last usable address?"*
  → `calculate_cidr` returns `1022` usable hosts, last host `10.20.3.254`, and `routable: false` (it's RFC 1918 private space).
- *"Here's the token from the failing request. Why is the API rejecting it?"*
  → `decode_jwt` shows `"state": "expired"` with the exact `exp` date, or an `aud` that doesn't match your service.
- *"Is this certificate valid for api.example.com, and when does it expire?"*
  → `decode_x509` lists the SAN entries and an `analysis` block saying `active`, `pending` or `expired`.
- *"Seed the users table with 5 primary keys."*
  → `generate_uuid` with `count: 5` returns time-ordered v7 UUIDs, a good fit for database keys.
- *"Give me 3 short invite codes people can type without confusing 0 and O."*
  → `generate_nanoid` with `alphabet: "nolookalikes"`.

The agent then explains the result in plain language, but the facts come from
the tool.

## What happens on the wire

You don't need any of this to use the server, but it helps when debugging.
MCP is JSON-RPC over HTTP POST. You can call the endpoint with nothing but curl:

```bash
curl -s @@API_BASE@@/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{
    "jsonrpc": "2.0", "id": 1,
    "method": "tools/call",
    "params": {
      "name": "calculate_cidr",
      "arguments": { "cidr": "10.20.0.0/22" }
    }
  }'
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"network\":\"10.20.0.0\",\"broadcast\":\"10.20.3.255\",\"prefix\":22,\"subnetMask\":\"255.255.252.0\",\"firstHost\":\"10.20.0.1\",\"lastHost\":\"10.20.3.254\",\"totalAddresses\":1024,\"usableHosts\":1022,\"routable\":false}"
    }]
  }
}
```

Use `"method": "tools/list"` instead to see every tool with its JSON Schema. If the
input is invalid (say, a `/33` prefix), the result comes back with `"isError": true`
and the same error message the REST API would return, so the agent can read it and
correct itself.

A few design choices worth knowing:

- **Stateless.** Every POST is self-contained, so the server runs on Cloudflare
  Workers with no session storage. `GET` and `DELETE` on `/mcp` return `405`.
- **Plain JSON responses.** None of the tools stream progress, so responses are
  regular `application/json` rather than an event stream.
- **Token-conscious output.** `decode_x509` omits the raw signature bytes (hundreds of
  hex characters an LLM has no use for). Fingerprints are still included.
- **Inputs are never echoed back.** Decoded JWTs and certificates don't include the
  original token or PEM in the response.

## Before you paste secrets

<Callout type="warning">
The JWT and certificate decoders **do not verify signatures or chains**. "Decoded"
does not mean "trusted". Also remember that anything you give an agent travels to
both your LLM provider and the tool server. Don't paste production tokens that are
still valid. Use expired or test tokens when you can.
</Callout>
