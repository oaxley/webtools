WebTools Architecture

pnpm monorepo · React SPA on Cloudflare Pages · Hono Worker serving REST + MCP · one shared core library

Request flows

  • • Most tool pages compute in the browser with @webtools/core, so nothing is sent anywhere
  • • /my-ip fetches /api/v1/myip on the same origin; the Worker reads CF-Connecting-IP + request.cf
  • • REST and MCP clients reach the same Worker; each MCP tool mirrors a REST route
  • • In dev, Vite proxies /api/v1/* to wrangler dev, so the same origin rules apply

Privacy & security

  • • No database, nothing stored or logged; payloads travel in POST bodies, never in URLs
  • • Cache-Control: no-store on generated secrets and caller-specific answers
  • • CORS closed by default; * only for the spec, allowlist for /myip
  • • Password check sends only a 5-char SHA-1 prefix to HIBP; IP location is approximate

Single sources of truth

  • • packages/core: one implementation for the browser, REST and MCP
  • • openapi.yaml: served spec, the /api page and contract tests
  • • src/tools.ts: home cards, header chips, sitemap, per-tool HTML and OG images
  • • site.config.ts: public URLs, overridable via VITE_SITE_URL / VITE_API_BASE_URL
